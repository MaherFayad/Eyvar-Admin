## 1. Purpose

A **weekly on-call grid** (7 days × 3 shifts × 2 tiers = 42 slots), an explicit **coverage-gap report**, and a **shift-handover** mechanism that reads the outgoing operator's open items from live ownership data rather than from memory.

Pane description, verbatim (L1743):
> "Who is actually reachable, hour by hour. A single standing assignment reads as coverage but escalates to somebody asleep — this names a person per shift and, more importantly, names the hours nobody covers."

Module header, verbatim (L19570–19591):
> "The panel had a single standing assignment: two names, valid forever. That is not a rota — it is a placeholder that reads as coverage. At 02:00 on a Friday it escalates to somebody who is asleep, and nothing in the system knows that.
> Three things make it real, and the second matters most:
> 1) A WEEKLY GRID — day × shift × tier. Somebody specific holds every slot, or the slot is visibly empty.
> 2) GAP DETECTION — the panel names the hours nobody covers. An empty slot that nobody has noticed is worse than no rota at all, because the escalation path looks populated right up to the moment it is needed. Night and weekend gaps are surfaced hardest: that is when cover is thinnest and incidents are worst.
> 3) HANDOVER — an outgoing operator hands over the items they still hold. Ownership (A1) already knows exactly what those are, so the handover note is generated from real state rather than memory."

`renderOnCall()` (L15789–15798) targets `document.getElementById('oncall-body')`.

Consequences, all verified:

The in-file comment at L15777–15784 explains that `onCallNameSimple` was renamed out of a name collision with the rota engine's `onCallName` — but the collision fix left the older feature's DOM host missing. It is documented in §15 as an appendix.

## 7. Rules / policy logic — written out exactly

### 7.1 `slotKey(day,block,tier)` — L19609
`day+':'+block+':'+tier` → `'mon:morning:primary'`.

### 7.2 `currentBlock(d)` — L19610–19620
```
h = (d||new Date()).getHours()
for each block b in DB.onCallSchedule.blocks:
    if (b.from < b.to)   { if (h>=b.from && h<b.to) return b }        // normal block
    else                 { if (h>=b.from || h<b.to) return b }        // the block that wraps midnight
return blocks[0]
```
⚠ Uses `new Date()` — the **real wall clock**. That is the *same* clock the panel's dominant time source uses: `nowMs()` is literally `function nowMs(){return Date.now();}` (**L14627**), and it drives `slaState`, `myOpenClaims`, `logAction`, the ledger and every staleness rule. So the rota does **not** disagree with the panel at large.
>
> The narrower, real observation is that a **second** reference exists: `REQ_NOW_REF` (L9555), seeded to the *labelled* demo date Thu 25 Jun 2026 09:14. It is **not frozen** — `tickEngine` advances it every tick (L9680, and the source comment at L9574 says so) — and it governs a specific set of surfaces: the subscription-request / renewal subsystem plus schedule and tenure arithmetic (L4709, L4726, L4746, L4859, L9567, L9647, L11109, L12392, L13288, L13376, L13590, L14215). Where the rota's "today" and one of *those* surfaces are shown side by side, the calendar dates differ — the rota says the real today, they say a date anchored on 25 Jun 2026. Nothing else in the panel is affected.

### 7.3 `currentDayKey(d)` — L19621–19629
```
b   = currentBlock(d)
idx = d.getDay()
if (b.key==='night' && d.getHours() < b.to) idx = (idx+6)%7      // roll back one day
return DAY_KEYS[idx]
```
Comment (L19622–19625): *"A night shift that started before midnight still belongs to the day it started on — otherwise the 01:00 escalation looks up the wrong person, which is exactly when it matters."*
The condition tests `b.key==='night'` **literally**, so renaming or adding a wrapping block would break the rule silently.

### 7.4 `onCallNow(tier)` — L19631–19642 — the lookup
```
tier  = tier || 'primary'
day   = currentDayKey(); block = currentBlock().key
ov    = DB.onCallSchedule.overrides
          .filter(o => o.day===day && o.block===block && o.tier===tier)
          .pop()                                    // LAST matching override wins
uid   = ov ? ov.userId : DB.onCallSchedule.assign[slotKey(day,block,tier)]
u     = uid ? DB.teamUsers.find(x=>x.id===uid) : null
return { userId:uid||null, name:u?u.name:null, day, block, tier,
         override:!!ov, covered:!!u }
```
Note `covered` is `!!u`, not `!!uid` — a slot assigned to a **deleted** user id reads as *uncovered* here but as *covered* by `rotaGaps()` (which only checks the id's presence). The two disagree.

### 7.5 `rotaGaps()` — L19650–19662 — gap detection
```
for each day in DAY_KEYS (7):
  for each block in blocks (3):
    for each tier in tiers (2):
      if (!assign[slotKey(day,block.key,tier.key)])
         push { day, block:block.key, blockLabel:block.label, tier:tier.key,
                severity: (block.key==='night' || WEEKEND.includes(day)) ? 'high' : 'normal' }
```
**The severity rule, exactly:** a gap is `high` if the block is `night` **or** the day is Friday/Saturday. Every other gap is `normal`.
Ignores `overrides` entirely — an override that covers a hole still shows as a gap.

### 7.6 `rotaStats()` — L19663–19669
```
total    = 7 × 3 × 2 = 42
gaps     = rotaGaps()
covered  = total - gaps.length
pct      = Math.round(covered/total*100)
highRisk = gaps.filter(g => g.severity==='high').length
```

### 7.7 `setRotaSlot(day,block,tier,userId)` — L19670–19677
```
if (!requirePerm('manage_settings')) return
if (userId) assign[slotKey(...)] = userId
else        delete assign[slotKey(...)]
logAction('rota_updated','settings',slotKey(...), 'On-call rota — {Day} {block} {tier} → {name|UNASSIGNED}')
renderRota(); updateOnCallChip()
```
⚠ No before/after payload is passed to `logAction`, so the audit row has **no diff** — you can see the new holder but not the displaced one.
⚠ `renderRota()` rebuilds all 42 selects on every single change.

### 7.8 `commitHandover()` — L19708–19732 — the handover mechanism
```
me       = meUser()                                   // {id,name,role} from CURRENT_USER_ID
toId     = #ho-to.value
notes    = #ho-notes.value || ''
transfer = !!#ho-transfer.checked
held     = myOpenClaims()
toUser   = DB.teamUsers.find(u => u.id===toId)        // comment: "nm2 resolves riders and captains, not team members"
rec = { id:'HO-'+pad4(DB.handovers.length+1), fromId:me.id, fromName:me.name,
        toId, toName: toUser ? toUser.name : toId,
        tsMs: nowMs(), block: currentBlock().key, day: currentDayKey(),
        notes, items: held.map(c => ({type:c.type, id:c.id})), transferred: transfer }
DB.handovers.unshift(rec)
if (transfer):
    for each c in held:
        o = DB.ownership[c.key]
        if (o) { o.ownerId = toId; o.ownerName = rec.toName; o.touchedAtMs = nowMs() }
logAction('shift_handover','ownership',rec.id, …)
closeModal(); refreshOwnershipSurfaces(); renderRota()
toast('🔁 Handover '+rec.id+' recorded — N item(s) transferred|kept','ok')
```
`o.touchedAtMs = nowMs()` resets the staleness clock, so a transferred item gets a fresh 30 minutes on the incoming operator's name.

### 7.9 `myOpenClaims()` — L18912–18916 — what "still holding" means
```
Object.values(DB.ownership)
  .filter(c => c.state==='claimed'
            && c.ownerId===CURRENT_USER_ID
            && nowMs()-c.touchedAtMs <= DB.ownershipConfig.staleMin*60000)   // 30 min
```
An item idle for >30 minutes is **excluded from the handover list** — it is considered auto-released (`whoHolds()` L18865–18875 flips it to `state:'released'`, `releasedReason:'stale'`, and logs `claim_expired`). So the handover deliberately hands over only *live* work.

### 7.10 `rotaBoot()` — L19825–19838 — the seeding rule
```
users = DB.teamUsers.map(u => u.id)                    // 5 ids
if (!users.length) return
for (di, day) in DAY_KEYS:
  for (bi, b) in blocks:
    for (ti, t) in tiers:
       if (b.key==='night' && di%2===0)            continue   // night holes
       if (WEEKEND.includes(day) && t.key==='escalation') continue // weekend escalation holes
       assign[slotKey(day,b.key,t.key)] = users[(di+bi+ti) % users.length]
updateOnCallChip()
```
Comment (L19822–19824): *"Seed a partial rota on purpose: a fully covered grid would hide the feature that matters, which is the panel telling you where the holes are. Nights and the weekend are left thin, as they usually are."*

**Deterministic seeded gaps — computed from the rule (di: sun=0…sat=6):**

| Rule | Days hit | Slots skipped |
|---|---|---|
| `night && di%2===0` | sun(0), tue(2), thu(4), sat(6) — 4 days × 2 tiers | **8** |
| `WEEKEND && escalation` | fri(5), sat(6) — 2 days × 3 blocks | **6** |
| overlap (`sat` night escalation counted twice) | sat night escalation | **−1** |
| **Total gaps at boot** | | **13 of 42** |

→ coverage **29/42 = 69%**, all 13 gaps `severity:'high'` (each is either a night block or a weekend day). The head strip therefore reads `Coverage 69%` and `⚠ 13 night/weekend slot(s) uncovered` on a fresh load.

### 7.11 `updateOnCallChip()` — L19813–19821 — the escalation surface in the top bar
```
o = onCallNow('primary')
#oncall-chip.textContent = o.covered ? '📟 '+o.name.split(' ')[0] : '📟 nobody on call'
#oncall-chip.className   = 'b ' + (o.covered ? 'b-grey' : 'b-red')
#oncall-chip.title       = o.covered ? 'On call now — {name} ({Day} {block})'
                                     : 'No one is assigned to the current shift — escalations have nowhere to go'
```
The chip lives at **L568** in the top bar, `onclick="go('settings',null)"` — note it navigates to Settings but does **not** switch to the rota tab (`go('settings')` ends with `switchSettingsTab('general')`, L8819), so clicking the chip lands the operator on the General tab.

**This is the entire escalation chain.** `onCallName` has exactly **one** call site (L14945). ## 13. Gaps, dead code, UNVERIFIED items

### Confirmed issues
1. **`renderOnCall()` is orphaned — `#oncall-body` does not exist** (L15790). The entire simple Primary/Secondary roster feature, `saveOnCall()`, `onCallNameSimple()` and `DB.onCall` are unreachable dead code. §1.1, §15.
2. **`DB.onCallSchedule.overrides` is read but never written** (L19634). The one-off-cover feature described in the data comment (L19605) has no UI, no function and no seed. The `' (cover)'` suffix (L19648) and `onCallNow().override` are permanently unreachable.
3. **The escalation tier never auto-escalates.** `onCallName('secondary')` has zero call sites. Nothing promotes a breach from `primary` to `escalation`, and nothing fires when the primary slot is empty — the notification just says `— NOBODY ON CALL —`.
4. **`currentBlock()`/`currentDayKey()` use the real wall clock** (`new Date()`, L19611/19622). This agrees with `nowMs()` (**L14627** = `Date.now()`), which is what SLA, ownership, audit and the ledger use — so the rota is on the panel's *dominant* clock, not a rogue one. It disagrees only with the surfaces anchored on `REQ_NOW_REF` (L9555, advanced each tick at L9680): the subscription-request/renewal pipeline and the tenure/schedule arithmetic. On those pages the labelled date is Thu 25 Jun 2026 while the rota's blue "current shift" highlight follows the viewer's real day. *(An earlier revision of this item said the rest of the panel runs on a frozen `REQ_NOW_REF`; both halves of that were wrong.)*
5. **`timezone:'Asia/Riyadh'` is decorative.** No conversion is performed; `getHours()` is the viewer's local time. An operator in another timezone sees a different "now" shift than the label promises.
6. **`commitHandover()` has no permission gate** (contrast `setRotaSlot`'s `requirePerm('manage_settings')` L19671). Any user can transfer another operator's… actually only their **own** claims — but they can transfer them to anyone, including the `Invited`, never-logged-in user `USR-4`.
7. **An `Invited` user is assignable to on-call** (the option list is built at L19748–L19749 and includes `Noura Al-Fahad`, `status:'Invited'`, `lastLogin:'Not yet'`, **L2837**). No warning.
8. **`setRotaSlot` logs no before/after diff** (L19674) — `auditDiffHTML` renders nothing for these rows, so the audit log records who now holds a slot but not who was displaced.
9. **`onCallNow().covered` and `rotaGaps()` disagree** on a slot assigned to a deleted user id: `covered` is `!!u` (false), the gap check is `!assign[key]` (not a gap). Such a slot appears covered in the grid and uncovered in the head strip.
10. **The `#oncall-chip` navigates to the wrong tab** — `go('settings',null)` ends with `switchSettingsTab('general')` (L8819), so the chip lands on General rather than On-call.
11. **Double confirmation on handover.** `guardAction('commitHandover')` wraps the commit, so the modal's own footer button raises a second confirm dialog.
12. **`renderRota()` rebuilds all 42 custom selects on every single slot change** (L19676) — an open dropdown's DOM is destroyed under the click.
13. **`me` is an unused local in `openHandover`** (L19681).
14. **Handover rows show no timestamp** — `rec.tsMs` is stored and never rendered (L19804).
15. **`this.value` is always `undefined` in the grid's onChange expression** (L19777) — the hidden-input fallback is doing all the work. §3.1.

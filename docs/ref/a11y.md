# Accessibility quick reference

Source: `DESIGN.md` §7. Target: WCAG 2.2 AA.

## Required ratios

| Content | Minimum |
|---|---|
| Body text, labels, badge labels, table headers, hints, placeholders | **4.5:1** |
| Large text — ≥24px, or ≥18.66px at weight ≥700 | 3:1 |
| Interactive boundaries — input borders, checkbox/radio outlines, focus rings, selected-tab underlines | **3:1** |
| Graphics needed to understand content — chart strokes, status dots, progress fills | **3:1** |
| Decorative rules, dividers, card hairlines | none |
| Disabled controls | none |

Note: at 13px body, **no Eyvar text qualifies for the 3:1 large-text tier.** Everything is
4.5:1.

## The checks that catch most defects

- [ ] Visible focus ring on every interactive element. `outline: none` with no replacement
      is a defect (§7.2), not a style choice.
- [ ] Clickable things are `<button>` or `<a>` — never `<div onClick>` (§7.4). The legacy
      app has 253 non-focusable click handlers; do not add the 254th.
- [ ] Hover-revealed row actions also appear on `:focus-within` (§7.3).
- [ ] Colour is never the only carrier of meaning (§7.5) — a breached row says `overdue`,
      it does not merely turn red.
- [ ] Every `<th>` has `scope`. Every input has an associated `<label>`.
- [ ] Icon-only buttons have an accessible name.
- [ ] Toasts and validation summaries announce via `aria-live` — and a toast is never the
      only carrier of information (§7.5).
- [ ] `prefers-reduced-motion` kills every ambient loop (§7.6).

## Testing it fast

Tab through the whole screen without touching the mouse. If you lose the focus ring, or
you cannot reach a row action, stop there — that is the finding.

# The string layer

Source: `DESIGN.md` §9 + `design/16-the-other-half.md` §1 + `design/18-pwa-arabic-and-voice.md`
Part 2. **`rtl.md` answers "does this mirror?" — this file answers "is this string
translatable at all?"** Two different failures. A screen can mirror perfectly and still be
untranslatable.

## The one number that governs the plan

**Do not quote a number from memory — read the generated one.**
[`docs/08-i18n/KEYS.md`](../08-i18n/KEYS.md) has the total, the per-`copy.ts` breakdown, what
Arabic is missing, and which screens have no `copy.ts` at all. It is emitted by
`scripts/i18n-inventory.py` and `npm run i18n:check` fails a build when it is stale.

```bash
npm run i18n:keys     # regenerate
npm run i18n:check    # what CI runs
```

It is **over four thousand keys**, not the 200 `dictionaries.ts` claimed for most of the
project's life. That estimate was an order of magnitude low and several schedules were sized
against it. The header now carries the generated figure, the script rewrites it, and
`src/lib/i18n/inventory.test.ts` asserts it against `Object.keys(EN)` at runtime, so it
cannot go stale between generator runs. **Do not hand-edit it.**

## `AR = {}` is deliberate — do not "fix" it

`src/i18n/dictionaries.ts:766` is `export const AR: Dictionary = {}`, and the header above it
records why: an empty dictionary is the AC-74 fixture proving the fallback chain works, and
translation is a content decision, not an engineering one.

The consequence people get wrong: **every screen renders English today.** So "screen X is
untranslated" is never a finding — it is the current state of all of them. The finding is
always *"screen X cannot be translated even once a dictionary exists."*

### A3, as built

**Eight render sites**, not two — `TicketsScreen.tsx`, `TicketDetailScreen.tsx`,
`AdminActivityScreen.tsx`, `RevenueScreen.tsx`, and both the rail and the drawer in
`components/profile/` (twice each, ticket + complaint). All eight now go through
`reasonLabel(t, code)`.

`reason.*` lives in **`src/i18n/vocabulary/copy.ts`**, not in a screen's `copy.ts`: the same
`CAP_LATE` lands on a ticket, a complaint, a fairness case, a ledger posting, a refund and an
audit line, so it is owned once and inherited — the shape `screens/queues/copy.ts` already
uses. It is spread into `EN` like any screen dictionary.

**The raw code is deliberately kept on two surfaces**, as a `font-mono` secondary line under
the sentence, wrapped in `<bdi>`: the ticket detail pane and the Admin › Activity reason
column. Both are handoff surfaces — a support operator escalating to engineering quotes the
code, and an investigator matches it against a ledger posting. It is never the primary label
and never repeats down a queue. `AdminTeamScreen.tsx:649` already showed a permission key
this way, so this is the console's existing shape rather than a new one.

**The `perm.*` half of the row above was WRONG and is struck.** There are **21** permission
labels, complete against all 21 members of the `PermissionKey` union, under
`account.permission.*` in `dictionaries.ts:429–453`. `AdminTeamScreen.tsx:647` and
`AccountLayer.tsx:527` both render them. The finding was true only of the *namespace name*.
Do not create a `perm.*` duplicate.

## `defaultValue` — the rule

```ts
// translate.ts:98
const template = dictionary[key] ?? fallback[key] ?? (params as any)?.defaultValue
if (template === undefined) return onMissingKey(key)
```

`defaultValue` is a third fallback the guard never sees. **Never add a new one.** A string
worth rendering is worth a key. When you delete one, the key goes in the owning `copy.ts`,
not in `dictionaries.ts` — `dictionaries.ts` is shell and cross-cutting only.

**This is now enforced, not asked for.** `scripts/i18n-budget.json` holds a ceiling;
`npm run i18n:check` fails when the measured count exceeds it and names the files; the
generator **refuses to raise it**, so the number can only fall. There is no way to add one
and stay green.

`src/screens/operations/dispatch/copy.ts` is the worked example of removing a batch: 41
literals in three components became one reviewable `Dictionary`, reached through
`withFallback` (`screens/operations/localCopy.ts`) until the shell registers it.

## Pseudo-localisation — see the Arabic defect before Arabic exists

`src/lib/i18n/pseudo.ts`, `npm run dev:pseudo`, or `?pseudo=1` on any dev URL.

Every keyed string renders marked and **35% longer**: `'Save changes'` → `'⟦Šàvé çhàñgéš ṗšéûḋ⟧'`.
Three findings fall out of one pass:

- **plain text on screen was never keyed** — the bracket is the tell;
- **a bracket in the middle of a sentence** is AC-75, a sentence assembled from parts;
- **a box that clips at +35%** has no headroom for Arabic's +4–8% either.

`AR` is empty and every screen renders English, so this is the *only* way to fail a build on
an Arabic-shaped defect today — and doing it first is what stops the first Arabic release
being blamed for layout bugs that predate it (**A4**). Combine with the language switch for
the whole picture: `ar` gives RTL geometry and the Naskh ramp, pseudo gives the width.

CI builds the mode and `src/lib/i18n/pseudo.test.ts` sweeps every English key through the
transform — a template that loses a `{placeholder}` would crash a pseudo run instead of
reporting from it.

## What already works — do not rebuild it

- **Plurals** route through `Intl.PluralRules` (`src/lib/i18n/plural.ts`). Arabic's six CLDR
  categories are handled. Do not hand-roll a count branch.
- **Type floor** — `:root:lang(ar)` raises the ramp in `globals.css` (~:827). Naskh is
  self-hosted and leads the family stack (`globals.css:1185`).
- **Calendar** is pinned `ar-SA-u-ca-gregory-nu-latn` — Gregorian against a Hijri default,
  Western digits by Saudi digital convention.
- **Mirroring** has four regression suites. See [rtl.md](rtl.md).

## Bidi isolation

`src/lib/i18n/isolate.ts`. Wrap any **single LTR token inside a translated line**: IDs,
plates, IBANs, phone numbers, timestamps, currency runs, code. Without it a leading `+` or a
trailing `:` jumps to the wrong side of the string. This is the A2 fix, applied at the cell
renderer rather than 200 call sites.

**One correction, measured rather than reasoned.** `isolate.ts` pins eight run kinds `ltr`
because they carry no strong character. That is right for `+966 55 123 4567` and wrong for
`date` the moment the month is translated: `<bdi dir="ltr">25 يونيو 09:39</bdi>` renders
`25 09:39 يونيو` in Chromium — UBA W2 makes the digits after an Arabic letter Arabic
Numbers, two embedding levels up, and they jump the month. A run with no strong character
resolves LTR under `auto` anyway, so **`auto` is right everywhere `ltr` is right and right
where `ltr` is not.** `DataTable` isolates with a bare `<bdi>`.
